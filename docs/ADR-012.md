# ADR-012: Bronze Layer Schema, Ingestion Design, and Header Validation

- **Status:** Accepted
- **Date:** 2026-09-28 (Updated: 2026-10-02)
- **Deciders:** Data Platform Engineering
- **Phase:** Phase 3 — Ingestion + Bronze

## Context

Phase 3 establishes the ingestion pipeline loading raw source data from external healthcare registries (Ministry of Health Malaysia facilities master) and synthetic insurance domains (`customers`, `policies`, `claims`, `payments`) into the PostgreSQL warehouse.

The raw ingestion layer (Bronze) must store source data verbatim without premature cleaning, while maintaining auditability, provenance, and safeguarding against malformed source file schemas.

## Decision

1. **Untyped Business Columns:** All incoming business fields are stored as `TEXT` in the dedicated `bronze` schema. Type casting, standardisation, and domain constraints are deferred to the Silver layer (Phase 4).
2. **Metadata Columns:** Every bronze table includes four provenance and load-order tracking columns:
   - `_batch_id` (`UUID NOT NULL`)
   - `_source_file` (`TEXT NOT NULL`)
   - `_source_row_number` (`INT NOT NULL`)
   - `_ingested_at` (`TIMESTAMPTZ NOT NULL DEFAULT now()`)
3. **Append-Only Persistence:** Ingestion operations are strictly append-only. No `UPDATE` or `DELETE` operations are permitted on bronze tables.
4. **Single-Transaction COPY & Idempotency:** Each source file is ingested in a single database transaction using PostgreSQL `COPY`. Re-ingestion skips files whose SHA256 digest is already recorded as `SUCCESS` in `bronze.ingestion_log`, unless `--force` is supplied.
5. **Pre-Load CSV Header Validation:**
   - Prior to buffering and loading rows, the pipeline inspects the CSV header against the expected non-metadata columns of the target bronze table.
   - **Missing columns:** The batch fails immediately, rolls back any open transaction, and inserts a `FAILED` row into `bronze.ingestion_log` listing all missing column names.
   - **Extra columns:** The batch fails immediately, rolls back, and records a `FAILED` row in `bronze.ingestion_log` listing the unrecognized extra column names.
   - **Column order differences:** Differences in CSV column order compared to the database DDL are explicitly allowed; the pipeline maps columns dynamically in the `COPY table (...)` statement so fields load into the correct table columns.
6. **Comprehensive Audit Logging:** Ingestion runs record execution status (`SUCCESS` or `FAILED`), batch ID, file SHA256 checksum, row counts, and detailed error messages in `bronze.ingestion_log`.

## Consequences

- Ingestion boundaries are protected against malformed or drifting upstream CSV schemas before partial data is loaded.
- Corrupted or partial batches leave zero orphaned rows in bronze tables due to transaction rollback.
- Complete traceability and audit records are preserved in `bronze.ingestion_log` for failed and successful runs alike.
